# Office 原版磁盘元数据缓存（C9-BV）

固定目标 `38a6a5c965aa99ab525161efb7cc5cf1fe62fced`。浏览器扫描继续执行原版 SDK 的 readFontMetadataCache、writeFontMetadataCache、记录校验、摘要和扫描函数。Python 仅负责源文件的限额稳定读取、独占临时文件和原子替换；缓存文件不可用时仍是可选缓存未命中，取消原因继续传播，卸载等待拥有的文件操作。

持久化使用原版路径和原版 JSON 字节格式。浏览器私有卷中的 `/physical/` 路径在进入缓存前还原成实体路径，读缓存后再映射回私有卷；磁盘记录的摘要和字段校验全部由原版函数完成，记录仍需按当前实体文件的设备、inode、大小和时间戳验证。内存 previous 的优先级保持原版顺序。有效且不变的记录不重写缓存，禁用和限额行为也保持原版。

真实原版 Worker 与 Python/Chromium 对照在 x64、x86 各通过 8 组：首次写入、正常复用、有效元数据复用标记、错误摘要、额外字段、截断、超限、禁用。快照和缓存原始字节一致，浏览器写出的缓存由原版 Worker 消费；有效复用标记证明没有用重新解析字体替代缓存读取。103 项定向检查及最终 13 项默认服务/文件事务检查通过，两次资源构建的 27 份文件与提交内容逐字节一致。

默认服务测试现将 LOCALAPPDATA 定位到自有夹具，验证默认缓存目录的实际写入。首次默认目录检查可能触及了用户配置缓存；其先前归属不明，依照用户数据保留规则不删除或重置该目录。其余自有工作区、构建副本和重复缓存均已清理，40 份实际缓存观察按 SHA 去重保存，日志、XML 和原版快照保留。
