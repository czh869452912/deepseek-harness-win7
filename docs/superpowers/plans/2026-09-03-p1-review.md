## 3. Critical（必须立即修）

### C1. events.py emit 对 TypeError/ValueError 重试 → 监听器双重执行【本次引入的回归】
- 位置：`dsh/cordis/events.py:241-258`
- 行为：监听器**函数体**抛 TypeError/ValueError 时先按 info-dict 形状重试一次 → 执行 2× 后第二次异常才上抛。TS `events.ts:194-196` 每监听器仅执行一次、异常直接传播。所有 `internal/dispatch`、session 事件、lifecycle 通知都走 emit。
- 修复：删除 try/except 重试；internal/dispatch info-dict 适配改为纯签名判定（1 参监听器传 info，其余位置传参），与 bail/serial 现行做法一致。补测试钉住"单次执行"。

### C2. 插件服务在依赖触发 reload 后静默消失（fiber D12 + registry D2）
- 位置：`dsh/cordis/fiber.py:557-601`（`_reload` 复用 `self.plugin`）、`registry.py:263-294`
- 探针实证：`SvcPlugin(Service)` 依赖 dep；dep dispose+重提供后 fiber 回到 ACTIVE 但 `ctx.get("svc")` 为 None——provide teardown 在 `_unload` 执行后，唯一重提供方（构造器）从未重跑。TS `fiber.ts:250-257` 每次 reload `new runtime.callback(...)`。
- 修复：类插件实例化移入 `_reload`（每次 `cls(self.ctx, self.config)`），对象插件保持复用；`registry.plugin()` 保留形状解析/静态元数据解析（inject/provide/Config 提前建拓扑）。

### C3. fiber D7 启发式仍活体——schedule 插件被禁用
- 位置：`dsh/cordis/fiber.py:348-357`
- 探针实证：`dsh/schedule/__init__.py:104` `ctx.effect(unapply)` 命中无关键字 → **注册时被执行**，`agent/created` 监听器被立即注销，schedule 运行时 spawn 永久失效。另一失败模式：`ctx.effect(cleanup)`（cleanup 返回 disposer）注册时主体不执行、卸载时其返回的 disposer 被丢弃（`dsh/jobs/tool_jobs.py:132-139` 仅因"cleanup 主体即 teardown 且无返回值"而侥幸存活）。
- 修复：按 9d 报告修复方案——`Fiber.effect` 增加 `is_disposer: bool = False`；`Context` 增加 `ctx.disposable(fn)` 入口；默认（False）无条件执行并按 TS 分支解释返回值（非法形状 `TypeError("Invalid effect")`，ts:363,372,397）；落点后全库审计改名调用点（`session.py:994`、`agent.py:415`、`tool_pwsh.py:318` 迁移至 `ctx.disposable(...)`；`schedule/__init__.py:104` 改为 effect body 返回 teardown）。

### C4. 异步 apply 期间 dispose → effect 泄漏（fiber D13）
- 位置：`dsh/cordis/fiber.py:604-612`（`_async_wait_res` 无条件置 ACTIVE，无 epoch 复查）
- 探针实证：apply 注册 effect 后等待 gate；期间 `dispose()` → 最终态 DISPOSED 但 effect cleanup 从未执行（`set_epoch` 因 inertia pending 提前返回）。
- 修复：成功/失败两分支都做 epoch 复查 → `set_state(UNLOADING); self._unload()`（ts:665-672）。

### C5. `!!js` 在写回时被破坏（include D3 + profile D6）
- 位置：`dsh/cordis/include.py:208/234`（`yaml.safe_dump` 无 representer）、`dsh/cordis/profile.py:334-337`（`--dump-config` 同样）
- 行为：所有内置预设的 `disabled: !!js` 行在首次 Include 写回或 dump 后变成普通映射，磁盘方言被改写、无法循环重载。读取侧构造器已注册（loader.py:92-93），写入半边缺失。
- 修复：注册 `SafeDumper` representer：`{'__jsExpr': str}` → `!!js <scalar>` 节点。include 写回与 profile dump 共用。

### C6. 静默部分启动仍可能（loader D9/D14 + harness D3）
- 位置：`dsh/cordis/loader.py:532-539`（`await_tasks` `return_exceptions=True` 吞 fiber 失败）、`loader.py:1312-1316`（未注册插件仅告警）、`dsh/harness.py:172`（无 boot 审计）
- 行为：preset 引用未注册插件/激活失败时 `build_harness` 返回缺工具/服务的 ctx 且无错误——正是 17-harness 报告引用 TS `assertEntriesLoaded`/`assertEntriesActivated` 拒绝启动的失败类别。
- 修复：harness 侧落地审计：加载后扫描 `ctx.loader` entries——有 fiber 或 disabled 者之外 → 带标签 raise + 部分 dispose（ts:673-679, 707-740, 801-818）。
