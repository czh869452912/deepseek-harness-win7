# Office 实体字体提供层

C9-BO 在浏览器 SDK 外增加实体字体文件卷。目录以 UTF-16 顺序枚举，去重后保留规范路径字符作为私有卷内路径；HTTP 仅开放不透明的精确文件路由。SDK 仍负责字体解析、字形选择和缺失字体记录。见[精确检查](../../migration/candidates/rc022/office-font-volume-checks.json)。

每次打开都验证实体描述符身份和大小，读取受快照大小与字体上限约束，关闭前重查，并在结果发布前核验已观察路径。删除、替换、截断、增长、同大小修改及恢复 mtime 后的修改均有定向检查。Windows 从已打开句柄读取真实 ChangeTime，避免把 Python 的 Windows 文件创建时间当作 Node ctime；借用句柄由原始文件流关闭。

71 项检查及 16 组固定版实际 Node/WASM 与浏览器 SDK 对照通过。后者验证实体 dev/ino/size/mtime/ctime、字体属性和原有格式/图片行为。x86 Python 也实际完成字体读取、SDK 转换和回传前验证；四个字体的原始身份另与独立 Node BigInt fstat 对照一致。

扩展消费检查保留旧 Win32 oracle 的 a4c74a91/Node 22 基线身份。运行器版本选择错误修复后，还发现精确导入清单漏记此前引入的八个 Cordis 模块，已补齐并新增缺项/外来模块拒绝检查。此项消费回归与 rc022 的实际 Office 对照分别记录。

测试工作区、已消费的合成输入和中间输出均已清理；原元数据测试留下的四个只读合成文件，在核对归属、单链接及无剩余消费者后清除了各自属性并删除，没有批量修改共享文件。失败元数据观察、紧凑记录和最新实际输出保留供默认引擎编排使用。默认字体/Office 安装字体发现、缓存、默认引擎、Portable 与 Win7 实际验收继续推进。
