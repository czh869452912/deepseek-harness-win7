# 固定版 Office SDK 的浏览器适配

C9-BN 复用固定版 `@deepseek-ai/libreoffice-kit@0.2.3` 的原始字体扫描、匹配、文档检查、导出与栅格函数主体，只适配文件卷、哈希、模块加载和 worker 通道。原始入口包在异步函数中调用；原文件及许可声明保存在构建产物中。大型 WASM 仍使用已核验的外部原始资产。见[精确检查](../../migration/candidates/rc022/office-sdk-browser-checks.json)。

原始 Node/WASM worker 与 Python/Chromium 构建的 16 组实际对照通过，覆盖四个实体 TTF 字体的元数据、已安装和缺失字体、DOCX 多格式转换、文档与 PDF 图片，以及输入/输出/字体/归档限制。直接文档与 PDFium 图片的 PNG 原字节、尺寸、矩形和字体诊断相同。TXT 相同；带日期的 PDF/DOCX/ODT 不宣称逐字节相同。原文档图片已目视检查。

文件卷按描述符持有读取缓冲，关闭即释放；最终每组都确认没有未关闭描述符或卷内残留的读取缓冲。扫描不会为了建立元数据目录而一直保留全部字体原字节。x86 Python 也实际完成了 SDK 字体解析和 TXT 转换，但使用同一台 64 位系统的浏览器。

最终构建的 27 个文件可逐字节复现。原始 MPL 源码、包内许可文件及嵌入式版权头均保留；四个 npm 包没有独立许可文件，保留其原始 package.json 中的作者与许可声明，没有生成冒充上游的声明。构建过程因缺失文件而中断的诊断记录保留；中间构建、已消费的合成输入和旧矩阵输出已经清理，最新实际输出供下一部分对照。

此部分尚未实现实体字体源的动态身份检查、默认目录/Office 安装字体发现、元数据磁盘缓存或 SDK 的完整宿主编排。默认 Office 服务、表格重算、演示文稿、Portable 与 Win7 实际执行仍继续推进；定向结果不改变迁移状态或发行资格。
